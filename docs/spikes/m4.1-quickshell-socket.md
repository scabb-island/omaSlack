# Spike M4.1 — ¿Quickshell puede ser cliente directo del socket del daemon?

Fecha: 2026-11-26 · Quickshell 0.3.2 (de Omarchy) · Go 1.26.11 · Resultado: **sí, sin el puente `ctl --stream`**

## Pregunta

`design.md` dejaba abierta la Open Question 1: ¿el `Socket` de `Quickshell.Io` con un `SplitParser` entrega líneas NDJSON de forma confiable en un stream largo, o hace falta un `Process` con `omaslack ctl --stream` de puente?

## Cómo se probó

Código en `spikes/m4-quickshell-socket/`:

- `server/main.go`: un servidor Go que habla un mini JSON-RPC sobre NDJSON en un unix socket 0600.
- `client/shell.qml`: una config de Quickshell sin ventanas que recorre estas fases y al final imprime una línea `RESULT {json}`:
  1. **Arranque tardío:** el cliente arranca 2 s antes que el servidor y reintenta.
  2. **Ráfaga:** N eventos lo más rápido posible. Incluyen acentos, emoji, `\n` escapados y comillas, y uno de cada 2000 es una línea de 256 KiB. Se verifica la cantidad, el orden por `seq` y los bytes UTF-8 del texto contra lo que informa el servidor.
  3. **Latencia:** 200 pings secuenciales de ida y vuelta.
  4. **Intercalado:** el servidor manda un tick cada 5 ms (400 en total) mientras el cliente hace ping cada 20 ms.
  5. **Corte:** el servidor cierra la conexión y el cliente tiene que detectarlo, reconectarse y repetir el `hello`.
  6. **Congelamiento del shell:** un `Timer` de 16 ms mide la pausa más larga del event loop durante la ráfaga.

Para reproducirlo:

```bash
go build -o /tmp/spike-server ./spikes/m4-quickshell-socket/server
/tmp/spike-server -delay 2s &
QT_QPA_PLATFORM=offscreen quickshell -p spikes/m4-quickshell-socket/client/shell.qml
OMASLACK_SPIKE_BURST=100000 QT_QPA_PLATFORM=offscreen quickshell -p spikes/m4-quickshell-socket/client/shell.qml
```

| Medición | 20.000 eventos | 100.000 eventos |
|---|---|---|
| Recibidos / pedidos | 20.000 / 20.000 | 100.000 / 100.000 |
| Fuera de orden | 0 | 0 |
| Errores de parseo | 0 | 0 |
| Bytes de texto (cliente = servidor) | 3.235.133 | 16.220.117 |
| Línea más larga | 229.443 caracteres | 229.443 caracteres |
| Duración de la ráfaga | 215 ms | 983 ms |
| Eventos por segundo | ~93.000 | ~102.000 |
| **Pausa máxima del event loop** | **35 ms** | **33 ms** |
| RTT de ping p50 / p99 / máx | 0 / 1 / 1 ms | 0 / 1 / 1 ms |

Fases que no dependen del volumen (corrida de 20.000):

- **Intercalado:** llegaron 400 de 400 ticks, en orden. Los pings durante el intercalado tuvieron p99 de 1 ms.
- **Corte:** el cliente detectó el cierre en 0 ms y volvió a hacer `hello` 252 ms después (el reintento estaba en 250 ms).
- **Arranque tardío:** 9 reintentos hasta que apareció el socket, y después funcionó normal.

## Conclusiones

1. **El `Socket` directo alcanza.** No hace falta el puente `ctl --stream`, y nos ahorramos un proceso extra por shell. La Open Question 1 queda cerrada.
2. **El shell no se congela.** La pausa máxima no crece con el volumen: ronda los 33–35 ms, unos dos frames. Quickshell lee el socket por bloques y le devuelve el control al event loop entre uno y otro. Aun así, el daemon igual va a coalescer `unread.summary` (spec `daemon-api`), y la ventana va a paginar.
3. **Las líneas grandes no son un problema.** 225 KiB en una sola línea JSON pasan sin cortes. No hace falta otro framing.
4. **Hay que poner backoff a los reintentos.** Cada intento fallido de conexión deja un `WARN quickshell.io.socket ... ServerNotFoundError` en el log del shell. El `Service.qml` real tiene que reintentar con backoff exponencial (de 1 a 30 s) y dejar de intentar mientras el daemon esté apagado a propósito, para no llenar el log.
5. **Escribir es simple:** `write(json + "\n")` seguido de `flush()`. No apareció ninguna carrera entre requests y notificaciones.

## Límites del spike

- Corrió con `QT_QPA_PLATFORM=offscreen`, en un Quickshell aparte del `omarchy-shell` real. El event loop es el mismo tipo, pero adentro del shell compite con el render de la barra. Lo vamos a volver a medir en M4.2, ya como plugin.
- Fue un solo cliente contra un solo servidor. Varios clientes (TUI y shell a la vez) se prueban en M2 con el daemon de verdad.
